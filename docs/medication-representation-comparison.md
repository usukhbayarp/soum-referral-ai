# Local medication/allergy representation comparison

**Decision: neither candidate is ready for integration.** This is a provisional development result, not clinical validation or held-out accuracy. The complete v0.6 referral application, production schema, prompts, defaults, model tags and historical results are unchanged. The clinician's proposed reduction from roughly 19 to 14 categories has not arrived; no replacement schema was invented.

Fine-tuning and better local model selection remain active follow-up options. This experiment does not decide to reduce the product permanently to medication extraction, and the hackathon deadline is not the basis for rejecting either option.

Both representations receive identical ordered paragraphs and source units, with one `U<number>` namespace. Each U ID maps to the existing deterministic `sentence-lines-1` unit, original text and original character offsets. Model presentation removes only annotation-only leading `[Sxx]` prefixes and omits offsets. No clinical heading, clinical fact or inferred date is inserted into the note. Original notes/offsets remain in the saved mapping. There is no sentence-context truncation; every unit is visible to both candidates.

## Candidates and one bounded revision

**A — `medication-A-1` / `medication-A-2`:** one required enum value for every actual U key. Roles are regular, encounter-administered, historical, planned/prescribed, explicitly not administered, allergy, mixed/unclear and other. Code assembles verbatim source groups with their original offsets. Mixed/unclear stays visible as review-needed; other is retained and audited for missed medication/allergy facts. No dose, route, time or treatment-row parsing is performed by A.

**B — `medication-B-1` / `medication-B-2`:** medication entries with role, exact documented name, nullable dose/route/time/frequency, and linked source-unit/quote evidence. Intact allergy statements are separate. A `medication_context` list preserves non-row facts such as “today's dose not asked” or “no treatment,” including when there is no named drug. This avoids inventing anonymous medication rows to hold negatives. It is an experimental contract, not a production-schema change.

B checks strict structure, exact quote occurrence in its linked original unit, every populated detail appearing in that entry's quoted evidence, and intact statement wording. Code computes quote offsets. Repeated text is scoped to its U unit; multiple matches within that unit retain all possible locations and get an ambiguity flag. All drug-detail-role associations are explicitly flagged for review; cross-unit associations get an additional flag. **Lexical validity never proves a correct association.** For example, a paracetamol time can occur in the same sentence as amlodipine and still be the wrong time for amlodipine. Negative wording can occur verbatim yet be nonsensical as a dose. Raw invalid proposals remain unchanged, with no repair or partial-list acceptance.

V1 used concise English instructions/definitions. Its observed regular/administered swaps, misplaced allergy negatives and B route/frequency/evidence-copying errors motivated **one** development-only revision for each candidate: Mongolian instructions and shared Mongolian role definitions, plus explicit B field distinctions and exact-copy guidance. This revision was frozen in **`9a49f4a`**, before its runs. [Revision rationale](../experiments/medication-v2/revision.json) records the changes. Notes, expectations, schemas, model and runtime settings stayed fixed. Changing language and instruction specificity together is not an isolated causal test. There were no further revisions, answer-key edits or retries until success.

## Interpretation and next comparison

**Neither** meets the integration rule: substantial useful coverage without observed role swaps, unsupported details or altered allergy meaning. The full referral product remains intact and neither experiment is wired into serving.

The failures are compatible with weak source/instruction distinction, Mongolian role comprehension and structured association following in this model/configuration. A avoids generated clinical values but does not fix classification; B exposes useful value fragments alongside harmful associations. All calls completed under the supported non-thinking mode, source/offset tests pass, model digest stayed pinned and no context truncation occurred. That reduces evidence for transport, ID-resolution or output-budget failure as the immediate explanation. It does **not** isolate model capacity from quantization, sampler, prompting or runtime/template effects. V2 changes language and specificity together. Output copied from instruction-like phrases is an observed pattern, not proof of a single cause.

**Single most informative next comparison:** this installed 1.7B against the **original `Qwen/Qwen3-4B` (not Thinking-2507)**, using the frozen A/B contracts, same local runtime, quantization class, notes and settings, under a separately named/digest-pinned artifact. [The original 4B model card](https://huggingface.co/Qwen/Qwen3-4B) explicitly supports `enable_thinking=False` and names local llama.cpp/Ollama support. On this already measured 16-GiB Apple-silicon machine, a 4-bit 4B checkpoint is a plausible local fit (estimate, not measured latency or guaranteed free-memory headroom). Verify its actual GGUF identity and non-thinking template in a tiny local smoke check before the controlled comparison. The installed `qwen3:4b` is Thinking-2507 and **must not be reused with `think:false` as a clean size comparator**. No replacement checkpoint was downloaded here. This next comparison still changes checkpoint and size together; it would not establish a pure parameter-count effect.

## Fine-tuning readiness — still an option, not started

The recurring errors—regular/administered/historical/planned distinctions, not-asked versus absent, drug–time/frequency binding, null discipline, and exact quote copying—are **plausible supervised fine-tuning targets**. Whether 1.7B can learn them reliably remains untested. Reviewed contrastive examples and a tiny train-to-serving experiment can test that; neither these failures nor the deadline proves fine-tuning impossible. Better model selection can proceed as a separate empirical option before choosing the training base.
