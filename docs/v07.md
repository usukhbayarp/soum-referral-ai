# v0.7 form and original-4B comparison

Form `experimental-0.7` implements the user's final specification, informed by the supplied DOCX (which still says 0.5). Experimental/unofficial; does not replace 13А. No clinical validation claim.

## Form mapping and preserved review behavior

The form has 72 fields, six sections, **19 unchanged model proposal categories**, and 53 manual fields. `config/referral.v0.7.json` explicitly maps the 19 names one-to-one to extraction schema `experimental-0.6`; output contract `source-id-v06-1`, production prompt `source-id-v06-1`, deterministic segmentation `sentence-lines-1` remain unchanged. Existing source-assignment datasets retain their own schema versions; medication experiments have the separate `medication-representation-1` contract. Moving fields does not change model categories.

Added optional birth date and receiving phone; demo ID suffices. Requested assistance is optional, separately labeled, never inferred from referral reason; populated values still print. Urgency remains a blank doctor selection with three choices, separate from source wording. History and regular medications share a visual group, not data/evidence. Diagnosis remains a documented assessment with optional codes.

Initial/current observations, arrival, document, exam and approval times remain distinct. SpO₂ is separate from oxygen support; documented device, flow with original units, and FiO₂ with original units are preserved. No automatic room-air inference, conversion or chronology. Either appropriate documented support detail can be recorded without demanding both flow and FiO₂; contradictory room-air/detail entries warn.

Additional information groups attachments, pending-result narrative/status/owner/method, future plan, transport and optional prior agreement. Only explicit doctor confirmation of pending results asks for owner/method. Unknowns remain visible. Organized medical transport requires vehicle/instructions and accompanying staff; planned referral alone does not. Optional agreement does not cause a universal warning. All populated fields remain printable with honest manual attribution.

Case reset, example replacement confirmation, source-change reconciliation, late-response rejection, invalidation and reviewed printing are retained. Source suggestions/debug controls remain in review, not export. No generated signature/stamp. The known extraction-limitations banner remains.

No saved-draft migration exists: all draft state is browser memory, never persisted. No fields were removed. Existing open tabs keep their current in-memory form; do not force-refresh an unfinished draft. New v0.7 pages warn before navigation/reload would discard a draft. Print/save an approved existing referral before manually reloading. Old approval is never imported into a new form/session.
